# 顧客資料高風險操作防護規格

## Objective

讓主管能在合併、還原、生日更正與刪除前看見影響，並讓已合併的顧客資料可安全撤銷；所有高風險動作須留下可查核紀錄，合併後自動維持點數與會員等級一致。

## Scope

- **Always**：合併前預覽交易／點數／等級影響；合併採軟合併且可撤銷；合併、撤銷、生日更正與刪除均要求理由與二次確認；每次操作寫入不可覆蓋的稽核紀錄；合併/撤銷後重算會員與點數餘額。
- **Ask first**：永久刪除任何顧客、交易或稽核資料；改變現行會員門檻或點數規則。
- **Never**：在未驗證的狀態下自動合併；刪除既有交易帳本；讓已軟合併的顧客再被一般輸入流程選取。

## Acceptance

1. 主管能先看到兩位顧客及合併後的消費、點數、等級、效期，再以理由＋確認送出。
2. 合併後來源顧客不刪除、不可被一般查詢/輸入選取，且可在沒有後續異動時一鍵撤銷並還原所有帳本關聯。
3. 合併、還原、生日修改與可刪除空白顧客均寫入 audit log。
4. 同名不同生日在審核頁保留為候選；一般輸入搜尋不回傳已合併顧客。
5. 自動化測試覆蓋預覽、確認拒絕、合併、撤銷、帳本還原、重算與 audit log；`db_check.py` 與正式站 smoke test 通過。

## Files

- `app.py`：schema、服務邏輯、路由與稽核。
- `templates/review.html`、`templates/merge_preview.html`：預覽／確認／撤銷 UI。
- `tests/test_contracts.py`：端到端契約測試。

## Deliberate boundary

不回溯改寫已發放的交易點數率。合併只重算目前會員狀態與可用餘額；歷史交易金額與已用點數帳本維持可稽核原樣。
